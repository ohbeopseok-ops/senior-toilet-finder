## 1. 타깃 페르소나 및 핵심 사용자 여정 (User Journey)

### 1.1 타깃 페르소나 (Target Persona)

| 항목 | 상세 내용 |
| :--- | :--- |
| **이름/연령** | 김영호 (만 71세, 남성) |
| **주요 생활 패턴** | 매일 오전/오후 근처 근린공원 및 천변 산책로에서 1~2시간 걷기 운동 수행 |
| **신체적 특성** | - 초기 노안 및 백내장 경향으로 대비가 낮은 작은 글씨(14pt 이하) 판독 불가<br>- 전립선비대증으로 갑작스러운 요의(급박뇨)가 잦아 10분 내 화장실 진입 필수<br>- 무릎 관절염으로 인해 가파른 계단이나 경사로 이용 시 낙상 위험 존재 |
| **디지털 리터러시** | - 카카오톡 기본 메시지 확인 및 유튜브 시청 가능<br>- 복잡한 필터링, 지도 핀치 줌(두 손가락 확대), 텍스트 타이핑 검색에 강한 거부감<br>- 화면 전환이 많거나 로딩이 3초 이상 지속되면 앱을 즉시 종료하는 경향 |

### 1.2 '운동 중 긴급 화장실 탐색' 3단계 원터치 여정 (User Journey)

복잡한 부가 기능을 배제하고, 신체적 긴급 상황에서 **"실행부터 길 안내까지 3회 미만 터치"**로 완료되도록 설계합니다.

```
[1단계: 즉시 진입]  
 스마트폰 홈 화면의 '안심화장실' 대형 바로가기(PWA) 1회 터치
       ↓
[2단계: 원터치 탐색]
 화면 중앙 '가장 가까운 화장실 찾기' 초대형 액션 버튼 1회 터치
 (현재 GPS 기반으로 반경 500m 내 '현재 개방 중 + 계단 없는' 최적 화장실 자동 선별)
       ↓
[3단계: 안전 도보 및 음성 안내]
 화살표 중심의 초대형 나침반형 길안내 화면 진입 + 음성(TTS) 즉시 시작
 ("전방 120미터 앞, 은혜공원 공중화장실입니다. 계단 없는 오른쪽 평지로 안내합니다.")
```

## 2. 공공마이데이터 및 공공 API 연계·활용 데이터 명세

### 2.1 공공데이터 및 마이데이터 연계 시나리오

1. **행정안전부 공공데이터포털 연계**
   - **전국공중화장실표준데이터 API**: 전국 공중화장실 기본 제원, 개방시간, 남녀구분, 비상벨 설치 여부 등 확보
   - **지자체별 개방화장실 실시간 현황 API**: 지자체 조례로 지정된 민간/공공 개방화장실 데이터 수집 및 주기적(1일 1회) 정합성 배치 처리
2. **보건복지부 / 행정안전부 공공마이데이터 연계 (선택적 동의 기반)**
   - **장애인 등록증 / 장기요양등급 / 보행약자 정보 연계**: 간편 인증을 통해 보행약자(휠체어, 실버카 이용자) 여부를 1회 확인 후 프로필에 저장.
   - **개인화 필터링 자동 활성화**: 마이데이터 인증 완료 시, 별도 설정 없이도 **'장애인 전용 대변기' 및 '휠체어 리프트/경사로 구비' 시설을 1순위로 자동 가중치 부여**.

---

### 2.2 핵심 데이터 수집 필드 명세서

| 필드명 (한글) | 시스템 필드명 (Key) | 데이터 타입 | 데이터 출처 | 활용 목적 및 시니어 친화 가공 방식 |
| :--- | :--- | :--- | :--- | :--- |
| **화장실명** | `toilet_name` | String | 공공데이터포털 | 시설명 축약 및 식별성 강화 (예: '은혜공원 남녀공용 공중화장실' → **'은혜공원 화장실'**) |
| **위치 좌표** | `latitude`, `longitude` | Float (WGS84) | 공공데이터포털 | 현 위치와의 유클리드 및 실제 보행 거리 계산 기준점 |
| **개방 시간** | `open_hours` | String | 공공데이터포털 | 현재 시간 기준 **[이용 가능 / 마감 임박 / 닫힘]** 상태 뱃지 생성 |
| **남녀 분리 여부** | `gender_separated` | Boolean | 공공데이터포털 | 시니어 안심 체감도 반영 (남녀 분리 시설 우선 정렬 가중치) |
| **무장애 편의시설** | `barrier_free_info` | Object | 표준데이터 + 지자체 | **경사로 유무, 장애인 대변기 유무, 안전손잡이(핸드레일)** 설치 여부 |
| **진입로 형태** | `entrance_type` | Enum | 국토교통부 보행로 API | 계단 유무(계단 없음, 경사로 완만, 계단 있음) 플래그 |
| **관리기관 연락처** | `manager_tel` | String | 공공데이터포털 | 긴급 상황 시 원클릭 전화걸기(`tel:`) 연결 |

## 3. 시니어 특화 UI/UX 설계 가이드

### 3.1 시각 가이드 (Visual & Accessible Design)

* **폰트 및 타이포그래피**:
  * 본문 기본 텍스트: **최소 19pt (25px) 이상**, 줄간격 160% 이상 유지.
  * 중요 알림/거리 표시: **32pt~44pt의 굵은 볼드(Bold) 폰트** 적용.
  * 가독성이 검증된 시스템 폰트(Pretendard GOV, Noto Sans KR) 적용.
* **고대비 컬러 팔레트 (WCAG 2.1 AAA 준수)**:
  * **주조색(Primary)**: Pure Black (`#121212`) 배경 또는 Deep Navy (`#0A192F`).
  * **강조색(Accent)**: Safety Yellow (`#FFD600` / 명도 대비 12:1 이상 확보) - 긴급 버튼 및 거리 표시에 사용.
  * **상태 표시**: 개방(녹색 `#00E676`), 종료(선명한 적색 `#FF1744`).
* **터치 영역 (Touch Targets)**:
  * 주요 인터랙션 버튼: **최소 가로 전체(Full-width) × 세로 64dp 이상**.
  * 부가 버튼: 최소 48dp × 48dp 이상 확보 및 버튼 간 마진(Margin) 16dp 이상 유지하여 오발화 방지.

---

### 3.2 내비게이션 및 기능 가이드

* **간소화된 맵 인터페이스**:
  * 복잡한 지도 위 마커 군집(Cluster) 제거.
  * 지도를 직접 조작하지 않아도, 화면 하단 카드에 **"남은 거리(m)", "소요 시간(보행속도 시속 3km 기준)", "직진/회전 화살표"**만 직관적으로 표시.
* **음성 안내(TTS) 연동**:
  * Web Speech Synthesis API를 활용하여 길 안내 시작 시 및 50m 전방 분기점에서 음성 안내 자동 재생.
  * 음성 볼륨 증폭 및 또렷한 한국어 안내 음색(속도 0.9배속) 기본값 설정.
* **배리어프리(무장애) 보행자 알고리즘 연계**:
  * 단순 최단 거리 대신, **경사도 8.3%(1/12) 이하의 완만한 길 및 보행로 단차 2cm 이하 경로**를 최우선 경로로 지정.

### 4.2 오프라인 및 통신 불안정 대응 캐싱 전략

공원, 천변, 하천 산책로 등 통신 음영 지역에서도 서비스가 중단되지 않도록 PWA Service Worker 및 브라우저 스토리지를 적극 활용합니다.

1. **에셋 캐싱 (Workbox Cache-First)**:
   - 정적 리소스(HTML, CSS, JS, 시스템 아이콘, 안내 음성 샘플)는 기기 로컬에 영구 캐싱하여 네트워크 단절 시에도 0.5초 내 로딩.
2. **반경 데이터 공간 인덱싱 (IndexedDB Pre-fetching)**:
   - 사용자가 위치 동의를 완료하는 시점에, 현재 행정동 기준 반경 2km 이내의 모든 공중화장실 메타데이터(약 50~100개)를 브라우저 `IndexedDB`에 JSON 형태로 로컬 저장.
   - 일시적 통신 두절 발생 시, 로컬 `IndexedDB`의 위치 데이터를 기준으로 Haversine 공식을 사용해 거리 계산 및 나침반 방향 안내 지속.

## 5. 시스템 아키텍처 및 구현 로드맵

### 5.1 기술 스택 아키텍처

```
[클라이언트 계층]
 - Next.js 14+ (React, PWA 지원 / next-pwa)
 - Styling: Tailwind CSS (고대비 테마 프리셋, em/rem 기반 유동 타이포그래피)
 - State: Zustand (간결한 상태 관리로 저사양 기기 메모리 점유 최소화)
 - Geolocation & Compass: W3C Geolocation API + DeviceOrientation API
 - Speech: Web Speech Synthesis API

[지도 및 경로 엔진 계층]
 - Map Rendering: Kakao Maps Web SDK / Naver Map SDK
 - Routing Engine: 국토교통부 무장애 도로망 데이터 기반 백엔드 라우팅 API

[백엔드 및 데이터 파이프라인]
 - API Gateway & App Server: Node.js (NestJS) or Python (FastAPI)
 - Cache: Redis (공공 API 응답 캐싱 및 실시간 운영 상태 계산값 저장, TTL 1시간)
 - Database: PostgreSQL + PostGIS (공간 인덱싱 `ST_DWithin` 활용으로 초고속 반경 쿼리)
 - 배치 워커: 매일 03:00 공공데이터포털 동기화 및 결측 데이터 보정 파이프라인
```

---

### 5.2 4주 단위 단계별 실행 로드맵 (MVP Launch)

```
[1주차: 데이터 파이프라인 구축]
 ├─ 전국공중화장실표준데이터 수집/정제 및 PostGIS DB 적재
 ├─ 개방 시간 파싱 로직 및 실시간 상태 판별 모듈 개발
 └─ 반경 반환 공간 쿼리 RESTful API 구현 및 Redis 캐시 연동

[2주차: 코어 클라이언트 & 지도 연동]
 ├─ Next.js 기반 PWA 프로젝트 셋업 및 고대비 UI 컴포넌트 개발
 ├─ W3C Geolocation 기반 실시간 위치 획득 및 권한 거부 대응 Fallback UI 구현
 └─ 카카오/네이버 지도 SDK 연동 및 3단계 원터치 화면 흐름(Journey) 완성

[3주차: 시니어 특화 기능 & PWA 오프라인 고도화]
 ├─ Web Speech API(TTS) 음성 길안내 로직 연동
 ├─ Service Worker 에셋 캐싱 및 IndexedDB 오프라인 화장실 캐시 파이프라인 구축
 └─ Android Chrome / iOS Safari PWA 설치 배너 최적화

[4주차: 접근성 검증 및 필드 테스트]
 ├─ WCAG 2.1 AAA 명도 대비 및 터치 타깃 자동화 검사 (Lighthouse 95점+ 달성)
 ├─ 60대 이상 시니어 FGI(표적집단면접) 및 야외 산책로 현장 실증 테스트
 └─ 오발화/사용성 피드백 반영 후 정식 MVP 배포
```
